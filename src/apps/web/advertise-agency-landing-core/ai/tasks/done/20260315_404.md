# Plan: Common 404 page mechanism

**Status**: pending
**Date**: 2026-03-15

## Goal

Implement a unified 404 (Not Found) page mechanism across the entire site. Currently there is no catch-all route, no dedicated NotFound page component, and no static `404.html` for hosting platforms. The two portfolio pages have ad-hoc inline 404 handling with inconsistent markup.

## Current State

- **No catch-all route** — `src/router.tsx` has no `{ path: '*' }` fallback; unknown URLs render a blank `<Outlet />`
- **No dedicated NotFound component** — no `src/pages/NotFound.tsx` or similar
- **No static `404.html`** — SSG build (`dist/`) doesn't produce a `404.html` for hosting platforms (Nginx, Netlify, Vercel, etc.)
- **Inline 404 in portfolio pages** (inconsistent):
  - `PortfolioCategoryPage.tsx` (lines 37-52) — renders a `<section>` with `<p>` + `<Link>` when category not found
  - `PortfolioCasePage.tsx` (lines 37-48) — renders a `<div>` with `<h1>` + `<a>` when case not found; uses `min-h-screen` centering but without Header/Footer (renders outside `<App />` layout wrapper)
- **Existing 404 copy is portfolio-specific** — `portfolioConfig.notFoundCategory`, `portfolioCaseContent.notFound.{title,back}`
- **No global 404 copy** in data files

## Steps

### 1. Create global 404 data file

Create `data/content/config/notFound.json`:
```json
{
  "$schema": "../../_schema/schema/notFound.schema.json",
  "title": "Страница не найдена",
  "code": "404",
  "description": "Запрашиваемая страница не существует или была перемещена.",
  "backLabel": "На главную",
  "backHref": "/"
}
```

### 2. Create Zod schema + type module

Create `src/types/config/notFound.ts`:
- Define `NotFoundContentSchema` with fields: `title`, `code`, `description`, `backLabel`, `backHref`
- Parse and export const `notFoundContent`

### 3. Create a `NotFound` page component

Create `src/pages/NotFound.tsx`:
- Full-page centered layout: large "404" heading, title, description, and a CTA-style link back to home
- Use `Container`, `bg-background`, dark-mode-safe tokens
- Read text from `notFoundContent` (step 2) — component never imports `@data/` directly
- Reusable: could be rendered as catch-all route AND as inline fallback

### 4. Add catch-all route to router

In `src/router.tsx`, add inside `children` array:
```tsx
{ path: '*', element: <NotFound /> }
```
This ensures any unmatched URL renders the 404 page inside the `<App />` layout (Header + Footer stay visible).

### 5. Generate static `404.html` via SSG

In `src/plugins/ssgMetaPlugin.ts` → `buildIncludedRoutes()`:
- Do **not** add `/404` to `includedRoutes` (vite-react-ssg would try to match it as a route and SSG it).

Instead, as a post-build step or via `onPageRendered`, copy the catch-all rendered page to `dist/404.html`. Options:
- **Option A (preferred)**: Add a `onSSGComplete` step or a small Vite plugin `closeBundle` hook that copies `dist/index.html` → `dist/404.html` (since the SPA fallback renders the 404 page for unmatched routes via the `*` catch-all).
- **Option B**: Add an explicit `/404` path in routes that renders `<NotFound />`, include it in `includedRoutes`, and SSG will generate `dist/404/index.html` — then rename/copy to `dist/404.html` in `closeBundle`.

Either way, the result is a `dist/404.html` that hosting platforms (Netlify, Vercel, GitHub Pages, Nginx) serve for unknown paths with HTTP 404 status.

### 6. Add SEO meta for 404 page

In `ssgMetaPlugin.ts` → `onPageRendered`:
- For the `/404` route (or the catch-all), inject `<meta name="robots" content="noindex">` to prevent search engine indexing of the 404 page
- Set `<title>` to "404 — Страница не найдена — {siteName}"

### 7. Refactor portfolio inline 404s to use shared NotFound

In both `PortfolioCategoryPage.tsx` and `PortfolioCasePage.tsx`:
- Replace inline 404 JSX with the `<NotFound />` component **or** a lighter inline variant that is visually consistent
- Decision point: the portfolio 404s currently have contextual "back to portfolio" links (not "back to home"). Two options:
  - **Option A**: `<NotFound />` accepts optional props (`backLabel`, `backHref`) to override the defaults from JSON — portfolio pages pass portfolio-specific back links
  - **Option B**: Keep portfolio-specific inline 404s but extract shared styles/structure into a reusable `NotFoundMessage` UI component
  - **Recommended**: Option A — single component, overridable via props

### 8. Generate JSON Schema + update validation

- Run `pnpm gen-schemas` — should pick up the new `NotFoundContentSchema` and generate `data/_schema/schema/notFound.schema.json`
- Verify `scripts/validate.ts` covers the new file
- Create `data/_schema/examples/notFound.example.json` with `$schema` ref

### 9. Update documentation

- Update `CLAUDE.md` data architecture table (`config/` section) with `notFound.json` → `notFound.ts` → `notFoundContent`
- Update `ai/docs/architecture.md` with the new catch-all route and 404 mechanism
- Update `ai/docs/data-map.md` if applicable

### 10. Verify

- `pnpm dev` → navigate to `/random-page` → see styled 404 page with Header/Footer
- `pnpm dev` → navigate to `/portfolio/nonexistent-category` → see 404 with "back to portfolio" override
- `pnpm build` → verify `dist/404.html` exists
- `pnpm typecheck` + `pnpm lint` + `pnpm validate` pass

## Open Questions

1. **Design**: Should the 404 page have an illustration/icon (e.g., a magnifying glass or a lost astronaut), or keep it text-only and minimal?
2. **Static 404.html strategy**: Option A (copy index.html) vs Option B (dedicated /404 route + rename) — Option B is cleaner for SSG with proper meta tags
3. **Portfolio 404s**: Use the shared `<NotFound>` component with prop overrides, or keep separate inline fallbacks with shared styling?
