# Plan: Upgrade to Vite 8

**Status**: pending
**Date**: 2026-03-15
**Depends on**: [`20260316_reactRouterV7.md`](./20260316_reactRouterV7.md) — removes `vite-react-ssg` (the Vite 8 blocker)
**Source**: [Official Vite 8 Migration Guide](https://vite.dev/guide/migration) · [Vite 8 Announcement](https://vite.dev/blog/announcing-vite8)

## Goal

Upgrade from Vite 7.3.1 to Vite 8.x. Vite 8 replaces the dual-bundler architecture (esbuild for dev + Rollup for production) with a single Rust-based bundler — **Rolldown** + **Oxc** — delivering 10–30× faster production builds.

## Prerequisite

`vite-react-ssg` (peer dep `^2–^7`) is the only blocker. It is removed during the React Router v7 migration. **Start this plan after that migration is complete.**

After RR v7 migration, the Vite plugin will be `@react-router/dev/vite` (`reactRouter()`), which is confirmed Vite 8–compatible.

## Steps

### 1. Check ecosystem plugin compatibility

| Package | Check |
|---------|-------|
| `@react-router/dev` | Confirmed compatible — tested by Vite & RR teams |
| `@tailwindcss/vite` | Check Tailwind CSS v4 changelog/releases for Vite 8 support |
| `rollup-plugin-visualizer` | Rollup plugin — check if it works with Rolldown or if a replacement exists |
| `vite-node` | Used for running scripts — check Vitest/vite-node releases |

### 2. Upgrade Vite and related packages

```bash
pnpm update vite@^8.0.0
pnpm update @tailwindcss/vite@latest
pnpm update vite-node@latest
```

### 3. Update `package.json` — remove esbuild from onlyBuiltDependencies

Vite 8 no longer directly depends on esbuild. The `pnpm.onlyBuiltDependencies` array currently includes `"esbuild"`. After upgrading, if esbuild is no longer in the dependency tree:

```json
// Before
"onlyBuiltDependencies": ["esbuild", "sharp"]
// After
"onlyBuiltDependencies": ["sharp"]
```

If esbuild is still transitively present (some plugins may still use it), keep it.

### 4. Migrate `build.rollupOptions` → `build.rolldownOptions`

Per the official guide: `build.rollupOptions` is renamed to `build.rolldownOptions`. The old name is deprecated and will be removed in a future version.

**Current `vite.config.ts`**:
```ts
build: {
  rollupOptions: {
    output: {
      manualChunks(id) {
        if (id.includes('/react/') || id.includes('/react-dom/') ||
            id.includes('/react-router/') || id.includes('/zod/')) {
          return 'vendor';
        }
        if (id.includes('/lucide-react/')) {
          return 'icons';
        }
      },
    },
  },
},
```

### 5. Migrate `manualChunks` → `codeSplitting`

Per the official guide: object form `output.manualChunks` is removed; function form is deprecated. Rolldown provides the [`codeSplitting`](https://rolldown.rs/reference/OutputOptions.codeSplitting) option instead. See [Manual Code Splitting — Rolldown](https://rolldown.rs/in-depth/manual-code-splitting).

**Migrated config** (conceptual — exact syntax depends on Rolldown's `codeSplitting` API):
```ts
build: {
  rolldownOptions: {
    output: {
      codeSplitting: {
        groups: [
          {
            name: 'vendor',
            test: /[\\/](react|react-dom|react-router|zod)[\\/]/,
            priority: 20,
          },
          {
            name: 'icons',
            test: /[\\/]lucide-react[\\/]/,
            priority: 10,
          },
        ],
      },
    },
  },
},
```

**Action**: Read the [Rolldown codeSplitting documentation](https://rolldown.rs/in-depth/manual-code-splitting) at implementation time to confirm the exact API shape. The function-form `manualChunks` still works (deprecated) — could be kept temporarily if `codeSplitting` API differs.

### 6. Handle `rollup-plugin-visualizer`

The `rollup-plugin-visualizer` is a Rollup plugin used for bundle analysis (`pnpm analyze`). Options:

- **Option A (try first)**: Keep as-is — Rolldown has a Rollup compatibility layer and many Rollup plugins work unchanged
- **Option B**: If it breaks, check if `rollup-plugin-visualizer` has released a Rolldown-compatible version
- **Option C**: Use Rolldown's built-in analysis tools if available, or remove the visualizer temporarily

Test by running `pnpm analyze` after upgrade.

### 7. Verify custom plugins work with Rolldown

Per the migration guide, plugins that transform content to JS from another format need `moduleType: 'js'` in the return value.

**`themePlugin.ts`** — `load()` hook returns CSS (not JS), and it's for a virtual CSS module. The `RESOLVED_ID` ends with `.css`, so Rolldown should auto-detect the module type. **No change expected**, but verify.

**`imageResizePlugin.ts`** — uses `configResolved` and `buildStart` only. These are universal hooks. **No change needed.**

### 8. Check for CommonJS interop issues

Per the migration guide, Vite 8 changes how `default` imports from CommonJS modules work. The project uses ESM-only (`"type": "module"` in package.json). Dependencies to watch:

- `recharts` — check if it's CJS or ESM
- `class-variance-authority`, `clsx`, `tailwind-merge` — likely ESM, but verify if any import breaks

If a CJS dependency breaks, the temporary workaround is `legacy.inconsistentCjsInterop: true` in Vite config, but prefer fixing the import pattern.

### 9. Verify browser target change

Vite 8 updates default browser targets:
- Chrome 107 → 111
- Edge 107 → 111
- Firefox 104 → 114
- Safari 16.0 → 16.4

These align with Baseline Widely Available as of 2026-01-01. Fine for this project (no legacy browser requirements), but document the change.

### 10. CSS minification — Lightning CSS is now default

Vite 8 uses Lightning CSS for CSS minification by default (previously esbuild). The project already uses `@tailwindcss/vite` which integrates with Lightning CSS. **No action needed**, but note:

- CSS bundle size might change slightly (Lightning CSS has better syntax lowering)
- If CSS issues appear, `build.cssMinify: 'esbuild'` is available as a fallback (requires keeping `esbuild` as devDependency)

### 11. Update TypeScript types

The `tsconfig.app.json` has `"types": ["vite/client"]`. Vite 8 may ship updated client types. After upgrade:

- Run `pnpm typecheck` to verify

### 12. Verify the full build pipeline

```bash
pnpm typecheck       # TypeScript type-checking
pnpm lint            # ESLint
pnpm validate        # JSON schema validation
pnpm dev             # Dev server starts, HMR works
pnpm build           # SSG production build succeeds
pnpm preview         # Preview built site
pnpm analyze         # Bundle visualizer (if rollup-plugin-visualizer works)
```

Verify:
- All pages render correctly (/, /portfolio, /portfolio/:cat, /portfolio/:cat/:y/:m/:slug, legal pages, /order)
- Dark mode toggle works
- HMR works in dev mode
- SSG generates all expected files
- Image optimization plugin runs during build
- Theme CSS variables are injected
- SEO meta tags are present in built HTML

## Migration Path

Try **direct upgrade** first. The project is small, uses standard plugins, and has no complex Rollup/esbuild customization. The compatibility layer should handle the `rollupOptions` → `rolldownOptions` conversion automatically. If issues arise, fall back to the gradual migration path (install `rolldown-vite` on Vite 7 first to isolate Rolldown-specific issues).

## Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| `rollup-plugin-visualizer` breaks | Low | Non-critical (analyze mode only); can be removed temporarily |
| CJS interop changes break a dependency | Medium | Use `legacy.inconsistentCjsInterop: true` as temporary workaround |
| CSS minification differences | Low | Lightning CSS is already used via Tailwind; fallback: `build.cssMinify: 'esbuild'` |
| `manualChunks` deprecation | Low | Function form still works (deprecated); migrate to `codeSplitting` at leisure |
