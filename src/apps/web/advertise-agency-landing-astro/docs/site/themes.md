# Color themes

[Documentation index](../../README.md)

The shared header provides a gear button named «Настройки» on desktop and mobile. `Settings.astro` owns its trigger, compact nonmodal panel, placement and focus/dismissal behavior; it nests `ThemeToggle.astro`, which owns only the native sun/moon/monitor radio row. The visible gear surface uses the same DaisyUI `btn-sm` sizing and shared radius as the desktop phone button, inside a centered clickable region of at least 44×44px. The theme row displays «Тема» on the left and a joined three-icon control with 32px-high surfaces, rounded outer ends and square inner edges. Each icon retains a 44px click target. There are no status or mode captions; a visually hidden fieldset legend and Russian names «Светлая», «Тёмная», «Системная» retain accessible semantics. The active icon has a doubled inset border and selected surface, while keyboard focus adds a separate outer outline. Russian native tooltips identify the modes. Unselected icons and the gear use a solid black hover surface with white icons in Light and the primary orange surface with contrasting icons in Dark; the selected radio uses the default cursor. The panel uses the smaller field radius. Choices apply immediately and leave the panel open. System keeps the monitor selected regardless of the effective OS appearance.

Enter/Space opens settings and focuses the checked radio; arrow keys use native radio navigation. Escape closes and restores gear focus. Tab/Shift+Tab follow document order and close when focus leaves both trigger and panel; returning to the gear stays within that boundary. Outside pointer actions close without cancelling their action or restoring gear focus. Mobile navigation closes settings before its modal opens, keeping the outside gear unavailable while the dialog is active. The header stays visible while settings is open and resumes its existing auto-hide rules after closing. Opening and changing themes preserve scroll position.

The solid panel aligns below the gear, clamps to 16px viewport clearance, scrolls internally in short viewports and updates on window/visual-viewport resize. Sizing uses actual compact contents, with bounded icon/gap/padding growth for enlarged text; an anchor ResizeObserver updates placement when its font size changes. Its coordinates account for the backdrop-filter header's containing block. At enlarged mobile text sizes the header wraps the brand onto its own row to keep settings and navigation reachable. Closed panel content is hidden from navigation and the accessibility tree. Settings interaction remains separate from the single pre-paint theme controller; no framework or new runtime dependency is used.

System is the default. A blocking inline script in the document head reads only valid `light`, `dark`, or `system` preferences from localStorage key `site-theme`, then sets `data-theme` and `color-scheme` before page content is parsed. Explicit choices override operating-system changes; System follows them. Local-storage events synchronize other tabs, including removal/clear; sessionStorage events are ignored. Invalid stored values fall back to System. Storage exceptions keep the current page usable with an in-memory choice; persistence across reloads is unavailable when storage is blocked.

Without JavaScript, the control stays hidden and CSS follows the operating-system theme. Pages and contact links remain available. The CSS fallback duplicates dark tokens from `global.css`; update both dark blocks together when changing the palette. Shared brand orange remains `#EA580C` in both themes.

No CSP is configured in this repository. If hosting adds a restrictive Content Security Policy, authorize the exact inline initializer using a hash (or a nonce for server rendering), rather than broadly permitting inline scripts. Otherwise the OS-based CSS fallback remains available, but saved choices cannot initialize. The initializer must remain a blocking head script; deferring it may cause a theme flash.

The external Yandex map iframe controls its own colors and does not follow site tokens. The local map placeholder retains its image colors. Photographs and external media are not recolored.
