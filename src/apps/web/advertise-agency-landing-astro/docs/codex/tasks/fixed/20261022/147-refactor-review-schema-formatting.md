# 147. Привести compile-time контракты review к правилам форматирования

Статус: завершено. Создано: 2026-10-22. Завершено: 2026-10-22. Приоритет:
низкий.

## Основание и границы

`src/validation/reviews.ts` содержит две compile-time проверки схемы и типа
`Review`, каждая из которых превышает установленный предел в 80 символов. Сейчас
их трудно быстро сверить с соседними экспортами и доменным контрактом.

Цель — оформить проверки на нескольких строках, сохранив те же типы схем,
направление сравнения и публичные экспорты.

Рабочий файл: `src/validation/reviews.ts`. Runtime-валидацию, поля схемы, данные
и контракты доменных типов не менять.

## Реализация

- Сверить `AGENTS.md`, правила разработки и задачу 031.
- Развернуть обе compile-time проверки в читаемый многострочный формат.
- Сохранить существующие тесты review-валидации и экспортируемые типы.

## Приёмка и проверка

- Ни одна строка файла не длиннее 80 символов.
- Compile-time проверки по-прежнему сверяют output схем с `Review` и `Review[]`.
- Запустить colocated suite `src/validation/reviews.test.ts`, `pnpm test:types`,
  `pnpm check:style` и ESLint для изменённого файла.
- После выполнения архивировать задачу по правилам
  `docs/rules/development/task-management.md`.

## Выполнение

Обе compile-time проверки развернуты на несколько строк. Сравнение output схемы
с `Review` и `Review[]`, направление проверки и публичные экспорты сохранены.
Runtime-схема, поля, данные и доменные типы не изменялись.
