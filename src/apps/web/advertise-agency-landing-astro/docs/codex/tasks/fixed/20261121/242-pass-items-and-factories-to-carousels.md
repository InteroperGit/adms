# 242. Перевести карусели на явные items и фабрику Item

- **Executor:** Sol (`gpt-6.2-sol`), reasoning: `medium`.
- **Tester:** Luna (`gpt-6-luna`), reasoning: `medium`.
- **Reviewer:** Luna (`gpt-6-luna`), reasoning: `medium`.

## Scope

- Перевести [CylinderCarousel][cylinder] и [ImageCarousel][image] на обязательные
  `Item` и `items` по образцу [CardCarousel][card]. `Item` — фабрика
  Astro-компонента (`AstroComponentFactory`), `items` — явный массив данных
  для слайдов. Карусель вызывает `Item` при серверном рендеринге для каждого
  видимого элемента в исходном порядке.
- Валидировать форму входных данных через существующие схемы Zod или
  `astro/zod`. Выдавать понятную ошибку с именем компонента и проблемным
  параметром при отсутствующих или неверных `Item` и `items`, невалидной
  записи массива и передаче дочерней разметки через slot, включая `ol` и
  `ul`. Обязательность параметров выразить также в типах.
- Сохранить правила пустых выборок. Вызывающая секция предложений скрывает
  карусель при отсутствии опубликованных элементов, а `CylinderCarousel`
  требует непустой массив. `ImageCarousel`
  принимает явно переданный пустой массив и сохраняет текущую обработку
  отключённой карусели и выборки, опустевшей после фильтрации.
- Оставить карусели владельцами структуры трека, навигации и метаданных,
  которые нужны runtime и доступности. Компонент `Item` отвечает за
  содержимое слайда. Переиспользовать существующие компоненты карточки и
  изображения, а также схемы загрузки контента.
- Обновить все прямые и косвенные вызовы, тестовые рендеры и контракты
  типов, затронутые новым API. Первичные потребители — предложения,
  секция «О компании» и галерея внутри карточки решения для бизнеса.
- Сохранить порядок и фильтрацию контента, ссылки, подписи и источник
  изображений, адаптивную геометрию, работу с клавиатуры и касанием,
  настройки анимации и HTML без JavaScript.
- Использовать [задачу 239][task239] как пример API. Учесть [задачу 241][task241]
  при проверке вложенной галереи, если секция уже использует внешнюю карусель
  карточек. [Задача 240][task240] использует уже готовый `CardCarousel`.

## Acceptance

- [x] Обе карусели получают обязательные `Item` и `items`. В каждом
      экземпляре фабрика получает пропсы конкретного элемента, а число
      и порядок отрендеренных слайдов соответствуют видимому массиву.
- [x] Отсутствующие `Item` или `items`, неверный тип фабрики, строка или
      объект вместо массива, значения вроде `null` внутри массива и
      дочерний HTML завершают серверный рендер понятной ошибкой.
      Пустой массив для `CylinderCarousel` также отклоняется.
      Схема изображений продолжает отклонять невалидные поля изображения
      и настройки карусели.
- [x] В предложениях первый слайд доступен без JavaScript. При включённом
      runtime работают цикл, соседние превью, стрелки, точки, ручная
      навигация и autoplay согласно настройкам. Неактивные слайды исключены
      из фокуса, а счётчик отражает только включённые предложения.
- [x] В «О компании» и в решениях для бизнеса фото, подписи, альтернативный
      текст, кадрирование и порядок совпадают с исходными данными.
      Контролы ссылаются на правильные ID, включая несколько галерей
      на одной странице. Для одного изображения и пустой выборки
      сохраняется прежний результат рендера.
- [x] На телефоне, планшете и десктопе сохраняются раскладка и навигация
      каждого варианта. Проверены клавиатура, видимый фокус, свайп,
      reduced motion и HTML без JavaScript. При наличии внешней карусели
      карточек переключение фото не переключает карточку решения.
- [x] Все производственные вызовы, тесты и типовые фикстуры используют

  он формирует слайдовые оболочки и начальное состояние доступности.
- `ImageCarousel` принимает обязательные `Item` и `items`, проверяет их
  существующими схемами, фильтрует элементы до построения слайдов и точек.
- `OffersCarouselView`, `About` и `BusinessSolutionGallery` используют новые
