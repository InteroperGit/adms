# 146. Привести форматирование парсера контента к правилам проекта

Статус: завершено. Создано: 2026-10-22. Завершено: 2026-10-22.
Приоритет: низкий.

## Основание и границы

`src/validation/parse-content.ts` содержит длинную сигнатуру `parseContent`
и длинное выражение формирования диагностик. Они превышают установленный
предел в 80 символов и затрудняют быстрый просмотр ошибок валидации.

Цель — разнести сигнатуру и преобразование ошибок на читаемые строки,
сохранив тип результата, порядок диагностик и текст ошибки.

Рабочий файл: `src/validation/parse-content.ts`. Схему валидации, контракт
ошибок и обработку runtime-контента не менять.

## Реализация

- Сверить `AGENTS.md`, правила разработки и задачу 031.
- Переформатировать сигнатуру функции и построение списка диагностик,
  не меняя публичную функцию и сообщение исключения.
- Сохранить существующие тесты парсера без изменения поведения.

## Приёмка и проверка

- Ни одна строка файла не длиннее 80 символов.
- Тип результата и диагностики `parseContent` остаются прежними.
- Запустить colocated suite `src/validation/parse-content.test.ts`,
  `pnpm check:style` и ESLint для изменённого файла.
- После выполнения архивировать задачу по правилам
  `docs/development/task-management.md`.

## Выполнение

Сигнатура `parseContent` и преобразование диагностик разнесены на читаемые
строки. Возвращаемый тип, порядок `issues`, формат пути и сообщение
исключения сохранены. Runtime-контент и схема валидации не менялись.
