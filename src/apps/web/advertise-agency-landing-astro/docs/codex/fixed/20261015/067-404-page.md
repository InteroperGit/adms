# Страница 404

Статус: completed. Дата реализации: 2026-10-15.

## Результат реализации

Создана `src/pages/404.astro` с общим Layout, noindex, одной основной
CTA-ссылкой на главную и дополнительными ссылками на проекты и контакты.
Ссылка на услуги выводится только при наличии видимых услуг. Собственных
клиентских скриптов у страницы нет. Использованы существующие Button,
theme tokens, focus styles и responsive container.

Проверки:

- `pnpm check` проходит; остаётся существующий Zod deprecation hint;
- `pnpm build` проходит: 39 страниц, включая `dist/404.html`;
- content boundaries и content invariants проходят;
- generated HTML содержит один h1, recovery content и noindex;
- dev-сервер возвращает HTTP 404 для обычного и вложенного неизвестного URL;
- Playwright проверил 320/768/1440 px без горизонтального overflow;
- проверены light/dark, keyboard Tab и видимый focus;
- без JavaScript страница читается, ссылка на главную работает;
- мобильный screenshot проверен визуально.

Evidence: `output/playwright/task-067-check.js` и
`output/playwright/task-067-mobile.png` (локальные игнорируемые артефакты).

Ограничения проверки:

  в project articles и отсутствующий loading у изображения на главной;
  ошибок для 404 нет;
- уже запущенный preview на 4323 использует старую таблицу маршрутов и не
  выдаёт новую 404. Последняя проверка preview в browser script завершается
  ошибкой; предшествующие dev/browser/no-JS проверки выполнены успешно;
- production hosting не изменялся; фактическую выдачу `404.html` и HTTP 404
  на нём нужно подтвердить при развёртывании. Dev HTTP 404 и файл сборки
  проверены отдельно.

## Цель

Создать понятную и доступную страницу ошибки 404 для несуществующих
маршрутов сайта. Страница должна сохранять визуальную систему сайта,
помогать посетителю вернуться к полезному содержимому и корректно работать
в production static build.

## Область работ

- создать `src/pages/404.astro`;
- использовать общий `Layout.astro` и существующие UI-компоненты;
- вывести явный статус `404` и короткое сообщение об отсутствующей странице;
- добавить основную ссылку на главную страницу;
- добавить полезные переходы к услугам, проектам и контактам;
- обеспечить корректную работу при отключённом JavaScript;
- сохранить светлую и тёмную темы, responsive layout и keyboard navigation;
- добавить уникальные `title` и description без индексации страницы ошибки;
- проверить, как Astro adapter/hosting отдаёт страницу и HTTP status 404.

## Контракт страницы

Страница должна содержать:

- один видимый основной заголовок;
- текстовый статус `404` с декоративной ролью, если он не является заголовком;
- понятное описание причины перехода;
- одну визуально приоритетную CTA-ссылку на `/`;
- вторичные ссылки только на существующие маршруты;
- достаточный focus indicator для каждой ссылки;
- семантический `main` и доступное имя страницы;
- отсутствие обязательной зависимости от внешних ресурсов.

Не добавлять интерактивное восстановление маршрута, автоматический redirect
или форму поиска без отдельного требования: посетитель должен самостоятельно
выбрать следующий маршрут.

## Реализация

1. Проверить структуру `Layout.astro`, header/footer и существующие design
   tokens перед созданием разметки.
2. Реализовать страницу как статический Astro-компонент.
3. Переиспользовать `Button` или другой существующий компонент ссылок, если
   его контракт подходит для CTA.
4. Добавить scoped styles с desktop/mobile состояниями и без layout shift.
5. Добавить комментарии к роли страницы, props и логическим секциям согласно
   `docs/development/rules/code-style.md`.
6. Проверить, что новая страница не требует JSON/MDX fixtures.

## Проверки

### Component/integration

- страница содержит ровно один `h1`;
- присутствует статус 404 и понятное сообщение;
- CTA ведёт на `/`;
- все вторичные ссылки ведут на существующие маршруты;
- ссылки доступны с клавиатуры и имеют видимый focus;
- разметка читаема без JavaScript;
- корректно подключаются Layout, header, footer и тема.

### Browser/E2E

- открыть существующий маршрут и получить HTTP 200;
- открыть несуществующий маршрут и получить страницу 404;
- проверить desktop и mobile viewport;
- пройти ссылки только клавиатурой;
- проверить светлую и тёмную темы;
- проверить generated HTML после `pnpm build`;
- проверить поведение при прямом переходе на вложенный несуществующий URL.

## Критерии приёмки

- `src/pages/404.astro` создан и использует существующий Layout;
- страница визуально соответствует сайту и не содержит placeholder-контента;
- основной путь восстановления — ссылка на главную страницу;
- отсутствуют client-side scripts, необходимые для чтения или навигации;
- 404 route не индексируется поисковыми системами;
- проходят `pnpm check`, `pnpm build` и `pnpm verify:quality`;
- browser-проверки подтверждают корректную выдачу страницы для неизвестного
  маршрута.

## Зависимости и риски

- фактический HTTP status зависит от adapter и настроек hosting;
- static preview и production hosting могут по-разному обрабатывать
  fallback-маршруты;
- нельзя считать `404.html` достаточной проверкой HTTP status без проверки
  развернутого окружения или adapter-specific smoke test.
