# 069a. Категории в карточках каталога

Статус: ожидает выполнения. Создано: 2026-10-11.
План: [Каталог проектов](../plan/20261010_050339_plan.md).
Зависимость: 069.

## Цель

Упростить верхнюю часть страницы `/projects/` и показать категорию проекта
в карточке единым овальным бейджем. Название и цвет категории должны иметь
один конфигурируемый источник и одинаково отображаться во всех местах,
где интерфейс выводит метку категории.

## Работы

- [x] На странице `src/pages/projects/index.astro` убрать видимые H1,
  заголовок каталога и поясняющий subtitle. Не удалять metadata страницы,
  хлебные крошки, поисковые controls, счётчик, состояния и сетку.
- [x] На странице каталога показывать только первые три публичных проекта
  в исходном порядке. Это ограничение относится к текущему каркасу страницы;
  будущий поиск и пагинация задач 070–071 должны работать с полным
  серверным набором данных, когда интерактивный каталог будет подключён.
  Не изменять общий источник `projects` и детальные страницы.
- [x] Создать JSON-конфигурацию категорий в `data/content/` со строгой
  схемой. Каждая запись должна содержать стабильный `slug`, русское
  отображаемое `label` и конкретный цвет фона для бейджа. Цвет хранить
  безопасным токеном (например, approved CSS color или design-token slug),
  а не собирать из пользовательского ввода.
- [x] Перенести текущий реестр категорий из TypeScript в этот JSON-источник
  или сделать проверенный loader из JSON. Сохранить тип `ProjectCategory`,
  строгую проверку неизвестных slug и отсутствие категории у проекта.
  Не оставлять второй редактируемый список labels/colors в TypeScript.
- [x] Добавить к `ProjectCard` овальный элемент `projectCategory`.
  Показывать label и настроенный фон категории, если `project.category`
  заполнена и найдена в конфиге; для null/unknown не показывать пустой
  бейдж и не придумывать категорию.
- [x] Использовать один компонент или helper для отрисовки category label
  в ProjectCard и будущих controls каталога. Не дублировать label/color
  локальными словарями в страницах и компонентах.
- [x] Настроить контраст текста на каждом фоне, видимый focus не связывать
  с бейджем, а округление сделать овальным (`border-radius: 999px`).
  Сохранить перенос длинных названий и отсутствие layout shift.
- [x] Обновить документацию категории и контракты, включая список цветов,
  формат JSON и правила добавления новой категории.

## Приёмка

- [x] На `/projects/` нет видимых заголовка «Проекты» и subtitle, но
  остаются breadcrumbs, controls, счётчик и карточки.
- [x] В каталоге отображаются ровно три публичные карточки или меньше,
  если опубликовано меньше трёх; draft не показываются.
- [x] Карточка с категорией содержит один овальный бейдж с русским label
  и цветом из JSON. Карточка без категории не содержит пустого бейджа.
- [x] Цвета и названия всех категорий задаются только JSON-конфигурацией;
  поиск по коду не находит дублирующих словарей labels/colors.
- [x] Категория в controls и бейдж используют тот же slug/label/color,
  а неизвестный slug обрабатывается безопасно.
- [x] Light/dark темы, мобильная ширина, длинный label, клавиатура,
  no-JS fallback и доступность не регрессируют.

## Проверка

Проверить JSON/Zod-контракт для неизвестного slug, пустой категории,
дубликата slug и недопустимого цвета. Проверить страницу с 0–3 публичными
проектами, демо и проектом без категории. Запустить `pnpm check`,
`pnpm build`, проверку контента, стиль и `git diff --check`.
