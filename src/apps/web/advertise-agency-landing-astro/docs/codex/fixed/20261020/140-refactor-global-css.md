# 140 — Разделить global.css и упорядочить темы и общие стили

**Статус:** Выполнена; ограничения общих TypeScript-проверок описаны ниже

**Создана:** 2026-10-20

**Реализована:** 2026-10-20

## Цель

Разделить глобальные стили по ответственности, устранить ручное дублирование
тёмной палитры и сделать порядок каскада понятным. Сохранить текущее оформление,
публичные классы, токены и поведение сайта.

## Результаты анализа

Анализ выполнен по исходникам; браузерные проверки и сборка не запускались.
Перечисленные риски каскада требуют проверки при реализации и сами по себе не
означают подтверждённых визуальных ошибок.

1. `src/styles/global.css` содержит 171 строку и объединяет пять ролей:
   Tailwind/DaisyUI, регистрацию токенов, палитры тем, базовые правила документа
   и общие классы компонентов. Единственное подключение находится в
   `src/layouts/Layout.astro:11`. Проблема в границах ответственности, а не в
   размере файла.
2. Тёмная палитра и две тени продублированы в `[data-theme='dark']`
   (`global.css:61`) и в системном fallback `:root:not([data-theme])`
   (`global.css:81`). В каждом блоке по 16 custom properties.
   `docs/site/themes.md` прямо требует менять обе копии. Исправление только
   одной копии приведёт к разному оформлению с JS и без JS.
3. Встроенные темы DaisyUI включены через `@plugin`, а проектные значения
   переопределяются отдельно вне CSS layers. Это два источника тематических
   настроек с разными приоритетами. При переносе правил важно сохранить значения
   и поведение переменных DaisyUI, которые проект не переопределяет.
4. `@theme` смешивает константы и ссылки на runtime-переменные:
   `--color-muted: var(--site-muted)` и
   `--color-control-border: var(--site-control-border)`. Для таких ссылок
   Tailwind описывает `@theme inline`. Требуется проверить сгенерированные
   utilities и их вычисленные значения, прежде чем выбирать форму объявления.
   Ошибка текущих utilities при анализе не подтверждалась.
5. Общий `:focus-visible` (`global.css:119`) зависит от токена
   `--content-block-focus-ring`, хотя применяется ко всему документу. Тот же
   токен используют `ParagraphBlock.astro` и `TableBlock.astro`. Общий фокус
   следует описать на уровне сайта, сохранив совместимый alias для блоков
   контента.
6. Правила расположены на разных уровнях каскада: `html` с плавной прокруткой и
   палитры находятся вне layers, базовые правила — в `base`, общие классы — в
   `components`. `scrollbar.css` импортируется первым и тоже содержит правила
   вне layers. Перестановка импортов или добавление layers может изменить
   приоритеты; переносить правила механически нельзя.
7. `@plugin` записан в одну строку, системный dark-блок имеет неверные отступы,
   а часть групп токенов и селекторов не объяснена комментариями. Это затрудняет
   чтение и безопасное изменение тем.
8. Общие `.site-*` классы используются layout, секциями и UI; токены
   `--content-block-*` — несколькими блоками контента. Их глобальная доступность
   обоснована. Scoped CSS компонентов уже отвечает за локальное оформление:
   переносить его в глобальные файлы не требуется.
9. По поиску в `src/` класс `.no-scrollbar` встречается только в
   `scrollbar.css`. Перед удалением проверить динамическое формирование классов
   и документацию; одного отсутствия статических совпадений мало.

## Предлагаемая структура

Сохранить единую точку входа `src/styles/global.css`, подключённую из layout.
Использовать существующий `src/styles/`, без новой системы сборки CSS:

| Файл              | Ответственность                                           |
| ----------------- | --------------------------------------------------------- |
| `global.css`      | Импорты, подключение Tailwind/DaisyUI, пояснение порядка  |
| `tokens.css`      | Регистрация utilities и общие токены геометрии/контента   |
| `themes.css`      | Light/dark, системный fallback, цвета и тематические тени |
| `foundations.css` | Типографика, focus/motion, общие `.site-*` классы         |
| `scrollbar.css`   | Существующая настройка скроллбаров                        |

Имена модулей можно уточнить при реализации; сохранить эти границы и не
создавать отдельный файл на каждый небольшой селектор. Импорты должны
образовывать один граф без повторного подключения Tailwind или DaisyUI. Порядок
исходных директив должен быть допустимым для CSS и текущего Tailwind Vite
plugin; проверить результат production-сборки.

## Объём работы

1. До изменений записать исходные вычисленные значения палитр, теней, радиусов,
   основных размеров, фокуса и прокрутки. Снять сопоставимые скриншоты главной,
   каталога, проекта, услуги и legal-страницы в обеих темах при ширине 320 и
   1440px. Использовать одинаковые synthetic fixtures.
2. Выделить модули и сохранить импорт `global.css` в `Layout.astro`.
   Зафиксировать порядок layers `theme`, `base`, `components`, `utilities` и
   назначение правил вне layers. Изменения приоритетов допускать только с
   объяснением и проверкой результата.
3. Определить единый источник каждой палитры. Рассмотреть штатные
   `@plugin 'daisyui/theme'` для переопределения light/dark и системной темы.
   Проверить сохранение существующих значений и наследуемых настроек DaisyUI.
   Если штатный механизм меняет поведение, использовать CSS aliases так, чтобы
   явная и системная тёмные темы ссылались на одни значения. Ручные копии тёмной
   палитры и теней устранить.
4. Сохранить приоритет явных light/dark над системной темой, работу
   `color-scheme` и CSS fallback без JS. Не менять раннюю инициализацию
   `ThemeInit.astro`, localStorage-контракт и контролы выбора темы.
5. Разделить константы и aliases в регистрации Tailwind. Проверить `text-muted`,
   `border-control-border`, `shadow-panel`, `shadow-elevated` и `rounded-panel`
   в сгенерированном CSS и в браузере. Не менять все объявления на
   `@theme inline` без разбора их назначения.
6. Ввести общий токен фокуса сайта и сохранить `--content-block-focus-ring` как
   alias. Сохранить 2px primary outline и 4px offset, ограничения анимации и
   отключение smooth scroll при `prefers-reduced-motion: reduce`.
7. Сохранить значения контейнера, ритма секций, заголовков, кнопок,
   `--site-header-clearance` и всех потребляемых `--content-block-*` токенов.
   Проверить явные scoped-переопределения, включая Footer и Settings.
8. Проверить scrollbar и `.no-scrollbar`; удалить только подтверждённо
   неиспользуемые правила. Отформатировать изменённый CSS по правилам проекта,
   пояснить назначение модулей, селекторов и media queries.
9. Обновить `docs/site/design-system.md`, `docs/site/themes.md` и
   `docs/development/project-structure.md`: источники токенов, порядок
   подключения, правила добавления общего/локального CSS. Удалить требование
   вручную синхронизировать два dark-блока.

## Проверки и критерии готовности

- `global.css` служит точкой подключения; ответственность каждого модуля
  описана. Tailwind/DaisyUI подключаются однократно, импортов по кругу нет.
- Явная и системная тёмные темы используют одни исходные значения палитры и
  теней. Light/dark сохраняют текущие цвета, включая неизменный brand.
- Сохранены `.site-*`, utilities и custom properties, используемые компонентами.
  Перенос не меняет специфичность и приоритеты незаметно.
- Расширены релевантные E2E-проверки: существующий `preferences.spec.ts`
  проверяет в основном `data-theme`, а `no-javascript.spec.ts` не проверяет
  палитру. Проверить вычисленные фон/текст, muted/control-border и обе тени для
  явных тем и системных light/dark без JS; проверить явную тему при
  противоположной системной настройке. Проверка одного атрибута недостаточна.
- Проверены видимый keyboard focus и reduced motion на уровне документа, а не
  только управление каруселью. При необходимости добавить узкие браузерные
  assertions в существующие specs.
- Сопоставлены скриншоты и исходные значения на выбранных страницах. Проверены
  размеры/отступы, кнопки, Settings, Footer, контентные блоки, якорная навигация
  и скроллбары. Нет новых визуальных отличий и overflow.
- Пройдены `pnpm check`, `pnpm build`, проверка форматирования изменённого CSS и
  обязательные проверки из `docs/development/verification-and-ci.md`. Выполнены
  затронутые E2E specs в Chromium, Firefox и WebKit:

  ```sh
  pnpm test:e2e tests/e2e/preferences.spec.ts \
    tests/e2e/no-javascript.spec.ts tests/e2e/responsive.spec.ts \
    tests/e2e/navigation.spec.ts tests/e2e/carousel.spec.ts
  ```

- Учтены уже описанные сбои из `docs/development/browser-coverage.md` и
  `verification-and-ci.md`: записать исходный результат и отделить существующие
  сбои от регрессий рефакторинга. Не объявлять проверки успешными по старым
  отчётам.
- В задаче записаны фактические изменения, результаты проверок и ограничения.

## Реализация — 2026-10-20

- `global.css` стал единой точкой подключения из 14 строк. Выделены
  `tokens.css`, `themes.css` и `foundations.css`; существующий scrollbar модуль
  сохранён. Вход из `Layout.astro` и scoped CSS не менялись.
- Основной plugin DaisyUI отключает автоматическую регистрацию тем.
  `daisyui/theme` расширяет встроенные light/dark, сохраняя прочие настройки.
  `prefersdark: true` генерирует системный fallback из единственного dark
  определения. Ручной второй копии палитры и теней больше нет.
- Темы перенесены из unlayered в `base` штатным механизмом DaisyUI.
  Геометрия/радиусы и scrollbar остались unlayered; `.site-*` сохранили
  `components`, типографика и доступность — `base`. Порядок layers объявлен в
  entry point, изменение приоритетов описано в документации и проверено.
- Два runtime color alias используют `@theme static inline`: utilities разрешают
  ссылку на элементе, а публичные переменные сохраняются в CSS. Общий фокус
  использует `--site-focus-ring`; старое имя контентного токена сохранено как
  alias.
- `.no-scrollbar` удалён после поиска в исходниках, скриптах, fixtures и
  документации: потребителей, включая динамическую сборку имени, нет. Остальные
  scrollbar-правила сохранили значения и приоритеты.
- Перед первым браузерным прогоном пришлось удалить три устаревших поля `notice`
  из synthetic проектов: текущий strict validator отклонял fixture и не давал
  собрать E2E preview. Runtime-контент не менялся.
- Добавлены две проверки системной палитры без JS и одна проверка документного
  focus/reduced motion. Проверки явной и системной темы дополнены вычисленными
  цветами, тенями, радиусами и utility-значениями. Helpers читают единый снимок
  стилей за один browser round trip.
- Обновлены design-system, themes, project-structure и browser-coverage. Новых
  зависимостей и runtime JS нет.

## Фактические результаты проверок

### Сравнение оформления

Сохранены 20 пар full-page скриншотов Chromium: `/`, `/projects/`,
`/projects/1/`, `/services/neon/`, `/privacy-policy/`, ширины 320/1440px, обе
темы, одинаковые synthetic fixtures и reduced motion. Исходные вычисленные
токены, стили элементов, размеры и scrollWidth совпали во всех 20 случаях. Новый
focus token добавлен без изменения прежнего `--content-block-focus-ring`.

Шестнадцать пар изображений совпали попиксельно. В четырёх снимках проекта
различаются 350–877 пикселей внутри области до 72×72px: визуально проверены
разные фазы нативного video loading indicator поверх `/favicon.svg` poster. Вне
этой области отличий нет. Это не изменение контентного layout или CSS.

Обнаружено и сохранено исходное поведение теней: Tailwind shadow utilities
компилируют светлые рецепты для обеих тем, прямые `var(--shadow-*)` получают
тематические значения. Это различие зафиксировано в assertions и документации.
Суммарный CSS E2E-сборки: 190016 → 189264 байта без сжатия.

Локальные ignored артефакты: `output/playwright/task-140/` — `before/`,
`after/`, `comparison.json`, crops, baseline CSS, исходный capture spec и скрипт
сравнения. Временный capture spec удалён из `tests/e2e/`.

### Браузерные сценарии

- Исходный полный прогон после ремонта fixture: 233/234 существующих E2E
  выполнений прошли, один Firefox test не создал страницу за 30 секунд.
  Дополнительно прошли четыре Chromium capture-сценария; восемь capture
  сценариев для других браузеров были намеренно пропущены.
- Первый затронутый прогон: 135/138 passed. Все 84 выполнения responsive и
  carousel прошли. Firefox navigation завершил assertions, но получил context
  teardown timeout с ошибкой software compositor. В WebKit новый focus test
  ошибочно предполагал первый Tab на ссылке; расширенная проверка тем также
  достигла общего таймаута.
- Исправлена проверка фокуса: Tab/Shift+Tab проходят через настоящий search
  input с общим outline; Settings имеет отдельный offset 2px. Чтение вычисленных
  стилей объединено, сокращая количество browser round trips.
- Финальный диагностический прогон: **54/54 passed** в Chromium, Firefox и
  WebKit, без retries и изменения таймаутов/assertions:

  ```sh
  pnpm test:e2e tests/e2e/preferences.spec.ts \
    tests/e2e/no-javascript.spec.ts tests/e2e/navigation.spec.ts \
    --workers=1
  ```

Один worker использован для диагностики исходной нестабильности создания и
закрытия Firefox context. Это отдельный результат; первый параллельный прогон не
объявляется полностью успешным. Исходные отчёты/трейсы сохранены в
`baseline-report/`, `baseline-results/`, `first-after-report/` и
`first-after-results/` внутри каталога артефактов задачи.

### Общие проверки и ограничения

Успешны: production build (39 страниц), `verify:boundaries`, `verify:content`,
`verify:component-tests`, `check:style`, ESLint изменённых E2E-файлов, Prettier
изменённых CSS/E2E/JSON и `git diff --check`.

Общие TypeScript gates **не пройдены** из-за существующих ошибок в других
тестах; эти файлы рефакторинг не изменял:

- `pnpm check`: шесть ошибок — `notice` в `ProjectCard.test.ts:14`,
  `tests/fixtures/content/type-contracts/project.ts:8`,
  `tests/integration/page-compositions.test.ts:261,601,759`, а также импорт
  удалённого `blockDemoNotice` в integration-файле на строке 47.
- `pnpm test:types`: то же устаревшее поле в type-contract fixture.
- Astro check также сохраняет прежний hint о deprecated Zod `finite()`.

Браузерные и визуальные проверки подтверждают рефакторинг CSS в описанном
объёме. Архивация задачи не означает прохождения перечисленных общих TS gates
или нового успешного полного E2E-прогона. Синхронизация остальных тестов с
удалением demo notices и нестабильность browser contexts остаются отдельными
работами.
