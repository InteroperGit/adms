# Каталог проектов: поиск, категории и пагинация

Дата: 2026-10-10. Статус: запланировано, реализация не начата.

## Цель

Создать отдельную страницу `/projects/`, на которой посетитель может
найти проект, выбрать тип изделия и переходить между страницами списка.
Сохранить существующие страницы `/projects/{id}` и раздел главной.

## Основание в текущем проекте

- Данные: `data/content/config/projects.json`, загрузка: `src/content/projects.ts`.
- Типы и Zod-схема: `src/types/project.ts`, `src/validation/projects.ts`.
- Карточка: `src/components/cards/ProjectCard.astro`.
- Главная: `src/components/sections/Projects.astro` выводит весь список.
- Детальная страница: `src/pages/projects/[id].astro`.
- Сборка статическая; отдельного маршрута каталога сейчас нет.
- Сейчас категория проекта хранится в `projectType` и влияет на форму
  световых букв. В рамках плана поле переименовывается в `category`.
  Световые короба и стенды отдельными значениями сейчас не представлены.
- Публичный список исключает draft и включает явно обозначенные demo.

## Предлагаемые решения

1. Использовать единое поле `category` вместо `projectType`: это одна
   сущность для фильтрации и выбора формы заявки. Переименовать поле
   в данных, TypeScript-контрактах, Zod-схеме и всех потребителях,
   включая страницы проектов, проверки, фикстуры и документацию.
   Переименовать связанные `ProjectType` и `projectTypes` в
   `ProjectCategory` и `projectCategories`; общий справочник содержит
   идентификаторы и русские названия.
   Начальный набор: световые буквы, световые короба, стенды, вывески,
   неон, объёмные конструкции, прочее.
   Существующие slug сохранить, добавить slug для коробов и стендов.
   Дополнять справочник централизованно; не хранить параллельно два поля.
2. Один проект относится к одной основной категории. Неизвестная категория
   допустима для старых записей: проект виден в «Все проекты», без выдуманной
   классификации. Перенести существующие значения в `category`;
   уточнить категорию по содержанию там, где добавлены более точные типы.
   Форму световых букв выбирать по `category === 'led-letters'`.
3. Страница содержит хлебные крошки, H1 «Проекты», поле поиска,
   выбор категории, счётчик результатов, сетку карточек и пагинацию.
   Использовать оформление, изображения и темы существующего сайта.
4. Поиск по названию, клиенту, краткому описанию и названию категории.
   Нормализация: регистр, пробелы, эквивалентность «е» и «ё».
   Все слова запроса должны встречаться в объединённых поисковых полях.
   Поиск и категория применяются совместно, затем выполняется пагинация.
5. Размер страницы: 12 карточек, фиксированный для всех экранов.
   Порядок сохраняется из источника данных; сортировку не добавлять.
   Показывать номера страниц, предыдущую/следующую и многоточия для
   длинного списка. При одной или нуле страниц скрывать пагинацию.
6. Состояние хранить в URL: `q`, `category`, `page`.
   Например: `/projects/?category=light-boxes&page=2`.
   Пустой запрос, «Все проекты» и первую страницу не записывать в URL.
   При смене запроса или категории сбрасывать страницу на первую.
   После перезагрузки и Back/Forward восстанавливать состояние.
7. Ввод поиска обрабатывать с задержкой около 250 мс и `replaceState`,
   явное применение поиска, выбор категории и страницы через `pushState`.
   Зафиксировать этот контракт в задаче до реализации, исключить дубли
   записей истории при отправке уже применённого запроса.
8. Для текущего небольшого каталога использовать Astro и небольшой
   TypeScript-модуль браузера. HTML всех видимых проектов формируется
   при сборке; скрипт управляет отображением. Без JavaScript остаются
   доступными весь список и ссылки; интерактивные элементы скрыты до
   успешной инициализации. Это не серверная пагинация: объём начального
   HTML зависит от всего каталога. При существенном росте пересмотреть
   решение на основе измерений, отдельно планируя индекс или сервер.
9. Черновики не передавать ни в HTML, ни в поисковые данные браузера.
   Демонстрационные проекты сохраняют заметное обозначение demo.
10. На главной оставить первые 3 проекта и ссылку «Все проекты».
    Из меню и детальных страниц обеспечить переход в каталог.
    `/#projects` продолжает работать как якорь раздела главной.
11. Canonical каталога указывает на `/projects/` без параметров.
    В sitemap добавить только базовый маршрут, учитывая текущую политику
    индексации и наличие production origin. Не создавать индексируемые
    страницы для каждой комбинации поиска и фильтра.

## Критерии готовности

- Прямой переход в каталог и на проект работает после статической сборки.
- Поиск, категория и страница дают согласованный список и счётчик.
- Ссылка на выбранное состояние воспроизводит результаты.
- Пустой результат предлагает сброс; пустой каталог имеет отдельный текст.
- Некорректные параметры URL приводятся к допустимому состоянию.
- Черновики отсутствуют в публичных данных, demo не теряет обозначение.
- `category` используется в данных, фильтре и выборе формы заявки;
  старое поле `projectType` и связанные контракты удалены из приложения.
- Клавиатура, мобильный экран, обе темы и режим без JS работают.
- `pnpm check`, `pnpm build` и применимые проверки контента проходят.
- Пагинация проверена на временных данных с более чем 24 проектами;
  тестовые проекты не добавлены в рабочий каталог.
