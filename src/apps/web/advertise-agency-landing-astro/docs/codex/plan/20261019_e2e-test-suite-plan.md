# План e2e-тестов

Дата: 2026-10-19. Статус: in progress; задачи 121-129 completed.

Цель: проверить основные пользовательские пути на production HTML и
разбить работу на короткие задания с ограниченным контекстом для Luna.

## Что уже есть

Инвентаризация выполнена по файлам репозитория; тесты при подготовке
этого плана не запускались.

- `tests/e2e/site.spec.ts`: 8 сценариев. Первый объединяет cookie,
  тему и мобильное меню. Остальные проверяют reduced motion, каталог,
  галерею, адаптивность, no-JS и два варианта отправки общей формы.
- `playwright.config.ts`: Chromium, Firefox, WebKit; общий fixture build,
  порт 4327, запрет reuse server, trace и screenshot при ошибке.
- `scripts/e2e-server.mjs` + `scripts/e2e.config.mjs`: production build
  и preview API. Данные копируются из версионных fixtures, артефакты
  находятся в `output/playwright/`.
- CI уже устанавливает браузеры и запускает `pnpm test:e2e`.
- Unit/render/integration проверки существуют. E2E дополняют их реальным
  фокусом, нативными диалогами, URL/history и сетевыми исходами.

Найденные пробелы: вручную созданный no-JS context не наследует
beforeEach блокировку сети; hostname-only правило разрешает лишние порты;
проверка отказа изображения не измеряет layout; нет самостоятельных
браузерных сценариев для conditional email и chart/video fallback.

## Как выдавать задания Luna

Модель: `gpt-6-luna`. Это инженерная оценка размера заданий,
а не результат сравнительного запуска моделей.

1. Один запуск получает один task file из таблицы ниже.
2. Обязательные инструкции: корневой `AGENTS.md`, правила из
   `docs/development/rules/`, затем только список «Прочитать».
   Весь план, историю fixed и соседние suites загружать не требуется.
3. Менять только файлы из разделов «Создать»/«Изменить или удалить».
   Исходники приложения в задачах указаны только для чтения.
4. Перед выполнением сверить наличие зависимостей; если ещё нет helper
   или fixtures, сначала закончить задачу-владельца.
5. Выполнить шаги и указанную команду. Тесты ниже являются явно заданной
   частью будущей реализации. Текущая работа создаёт только документы.
6. Вернуть: изменённые пути, краткий результат, команды/результаты,
   оставшиеся дефекты. Координатор обновляет статусы, `.codex/TASKS.md`
   и архивирует завершённые task files по правилам task-management.

Каждая задача содержит самостоятельные ограничения. Для 131 и 133
рекомендуется effort high, для остальных medium. Если нужна правка
production-кода или общий redesign harness, сохранить минимальное
воспроизведение и передать координатору. Не заставлять Luna искать
проблему во всём репозитории.

Готовый запрос исполнителю:

> Выполни только задачу docs/codex/todo/NNN-slug.md.
> Прочитай обязательные правила и перечисленные в ней файлы.
> Соблюдай список разрешённых изменений и критерии готовности.
> Запусти указанную проверку. Верни пути, результат и оставшиеся дефекты.

## Общие контракты

- Все spec импортируют `test`/`expect` из `./fixtures`.
  Каждый тест получает отдельный context; storage не протекает.
- Разрешён только origin `http://127.0.0.1:4327`. Внешняя сеть
  блокируется, endpoint отправки всегда перехватывается самим тестом.
- Runtime `data/content/` не читать и не менять для тестов.
  Новые versioned данные — в `tests/fixtures/content/`.
- Не добавлять production test routes и не переписывать unit suites.
- Ждать состояние через locator assertions / expect.poll / события.
  Не применять waitForTimeout, force:true, skip/fixme ради зелёного прогона.
- Для async fetch использовать управляемые Promise и освобождение в finally.
  Каждый тест отправки проверяет число запросов и payload там, где требуется.
- Селекторы: существующие data-атрибуты и id, доступные роли и имена.
  Тексты TEST_* брать из fixture JSON, не из runtime content.
- Строки кода до 80 символов. Astro-файлы читать с обязательным
  astro-best-practices; изменения Astro требуют отдельного описанного scope.
- Сервером управляет Playwright через webServer. Ручной dev server
  для этих задач не запускать; правило background dev относится к ручной работе.
- При отсутствии browser binaries установить их по существующей инструкции,
  с соблюдением sandbox permissions и sound-notifications.
- Найденный дефект: записать маршрут, browser, действия, ожидание,
  фактический результат и trace. Не ослаблять тест. До исправления
  приложения affected task остаётся незавершённой.

## Приёмка всего плана

- Исходные восемь сценариев сохранены по смыслу.
- Тесты разделены по поведению; общие network rules вынесены в один helper.
- Покрыты cookie/theme, меню, карусель, поиск/пагинация, галерея,
  обе формы, отказ media/runtime, no-JS и 24 responsive комбинации.
- Полный набор и повторный прогон проходят в трёх браузерах.
- В CI остаются тесты без skip и существующие артефакты диагностики.
- Runtime content и исходные общие site fixtures не изменены.
- Итоговое число тестов записывается после реализации, не предсказывается
  как достигнутое покрытие заранее.

Физические мобильные браузеры, реальный приём писем и успешное декодирование
видео не подтверждаются этим набором. Сложные таймерные ветви autoplay
остаются в существующих unit tests; новые E2E проверяют ручные действия
и reduced motion. SEO response/типовые render-контракты остаются в
существующих integration tests.

Данные формы световых букв: service route имеет синтетические разрешения
только в E2E сборке. Проект 1 остаётся demo; добавленные chart/video не
меняют категории, порядок проектов и исходную галерею.

Tasks 121-132 are completed and archived; tasks 133-136 remain pending.
