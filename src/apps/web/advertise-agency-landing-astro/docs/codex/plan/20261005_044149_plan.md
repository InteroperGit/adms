## Goal and placement

Add a compact «Горячие предложения» carousel to the homepage immediately below
the header and above About. Each offer contains an image, a short description
and a clearly named link button. Provide previous/next arrows, circular position
indicators with a selected current dot, and automatic slide changes. Preserve
the visually hidden homepage h1, existing sections and navigation, butterfly
branding, theme settings and cookie behavior.

Use an Astro component with a small browser script and existing design tokens.
No React or carousel dependency is needed. Apply frontend-design,
astro-best-practices and Playwright during implementation; consult the Astro
component, styling and content guides from [AGENTS](../../../AGENTS.md). Follow
[task management](../task-management.md).

## Content and configuration

Store settings and offers in `data/content/offers.json`, with validation and a
typed export following the project's existing content wrappers. Include
`enabled`, `autoplay`, `intervalMs` (default 7000, validated minimum 5000),
and an ordered `items` array. Each item needs a stable unique `id`,
`description`, `image`, `imageAlt`, `imageWidth`, `imageHeight`,
`linkLabel`, `href` and `enabled`, with validated presentation settings. Task
018b removes obsolete titles/credit fields, introduces accessible labels and
background focal-point settings, and updates contracts/validation together.
Validate positive dimensions, nonempty text, unique IDs and internal or HTTP(S)
links; reject unsafe schemes.

Task 018a adds remote HTTPS stock-image backgrounds and retained, clearly
identified test offers in `data/content/offers.json`, with JSON-editable
description font size, color and position. Use direct image URLs rather than
local background files and document source pages and usage terms. Provide
meaningful alt text or empty alt for an image that is purely decorative. Do not
invent discounts, prices, deadlines, client results or offer eligibility.
Missing approved promotional copy/artwork is an agency input. Demo content must
remain explicitly identified; never present arbitrary stock/project placeholders
as proof of a promotion. Approved production content remains a separate handoff.

Use explicit ordering and per-item enable switches rather than hidden sorting.
No scheduling, countdowns, tracking or inquiry form is required in this first
version.

## Rotation and interaction

Use one timer per carousel with clear start/stop logic. Autoplay starts only
when configured, more than one item exists, the carousel is visible in the
viewport, the document is visible, and reduced motion is off.

Task 020a supersedes task 020's explicit pause/play and persistent manual stops.
Remove the autoplay button. Rotation remains enabled whenever the JSON autoplay
setting is true; when false, rotation stays off. Pause temporarily on pointer
hover, focus within the carousel, hidden tab, offscreen state, page suspension
and reduced motion. Resume automatically with a fresh full interval when all
constraints clear. Manual selection resets the interval and never permanently
stops autoplay. Document these settings and automatic resume rules.

Auto-rotation never moves focus or announces each change. Manual changes may
update a concise polite status («Предложение 2 из 3»); keep automated changes
silent. Do not replace a focused CTA automatically. Optional touch swipe is
valuable if it remains a small implementation: horizontal gestures only,
threshold and direction checks, preserve vertical scrolling, and suppress
accidental CTA activation after a swipe. Buttons remain the primary alternative.
Avoid document-wide arrow-key interception; native Tab/Enter/Space must suffice.

## Accessibility and edge cases

Use a named region with carousel semantics, labeled slides and native controls.
Dots expose the selected position consistently (for example
`aria-current="true"` ); do not apply tablist semantics unless the full tabs
keyboard pattern is implemented. Hidden slides must be absent from the
accessibility tree and tab order. Retain visible focus and text/icon contrast
(4.5:1 normal text, 3:1 essential icons/controls).

- Disabled carousel or zero enabled items: omit the section and its controls.
- One enabled item: render a static offer without arrows, dots or autoplay
  controls.
- Multiple items without JavaScript: show offers as a readable stacked list with
  working CTA links; hide inactive JS controls. Enhance only after successful
  initialization so visitors do not lose content if scripts fail.
- Reduced motion: default to paused, no slide animation. User may navigate
  manually. Preserve readable content if storage or external assets fail;
  autoplay needs no storage or cookies.
- First visible image may be eager-loaded; remaining images load lazily or on
  approach to their slide. Avoid eager loading every offer or adding build-time
  downloads. Set priority only if this image is actually the likely LCP asset;
  measure rather than assume.
