# Code review plan

**Review date:** 2026-10-08

**Scope:** Astro pages and layouts, shared UI components, forms, content
validation, carousel behavior, project configuration, and existing verification
artifacts.

## Review result

`pnpm build` succeeds and produces all 11 routes. `pnpm check` reports zero
errors and zero warnings in application code, but reports one hint in
`output/playwright/task-018/matrix.js`: the `before` bounding-box value is
declared and never read. The project has no automated unit or browser test
script in `package.json`, so interaction and accessibility behavior is not
covered by the normal check command.

## Prioritized findings

### P0 — Enable a real inquiry delivery path before launch

`data/content/order-inquiry.json` deliberately leaves submission disabled and
without an endpoint. Both inquiry forms therefore prevent submission in the
browser and show an unavailable message. Confirm the production transport,
server-side validation, abuse protection, retention policy, and receipt
contract; then enable it only after consent copy and privacy/legal review.
Add a staging smoke test that verifies timeout, rejection, retry
deduplication, and the accepted receipt response without logging personal data.

### P1 — Add browser coverage for critical interactive behavior

The carousel, theme persistence, mobile menu, cookie banner, and inquiry
validation are implemented as browser scripts, but the package has no test
command. Add Playwright coverage for keyboard operation, reduced motion,
hidden-tab/offscreen autoplay pauses, static/no-JavaScript fallback, focus
retention, form validation, unavailable delivery, and theme changes across
reloads. Include narrow, zoomed, and short landscape viewports. Keep the
existing output matrix warning fixed or exclude generated artifacts from type
checking.

### P1 — Verify external media and third-party CSS at deployment time

Offers use remote Wikimedia images and the layout loads Font Awesome from
cdnjs. Define an asset policy and deployment check for availability, licensing
terms, cache behavior, and failure rendering. Prefer self-hosted or bundled
assets for critical icons and document any required external origins in the
site security policy. Test image failures while preserving reserved geometry
and readable CTA text.

### P1 — Establish a release metadata and SEO configuration

`astro.config.mjs` intentionally omits `site`, so canonical and Open Graph URL
metadata are absent from production output. Confirm the production origin,
set `site`, add sitemap/robots handling appropriate to the deployment, and
verify canonical URLs for every generated route. Add a release check that
rejects placeholder/demo promotional copy and missing social preview assets.

### P2 — Enforce the repository code-style contract

The project rule requires every line to be at most 80 characters and requires
purpose comments before Astro CSS rules. Existing components, validation files,
and configuration contain many longer lines and some dense declarations. Run a
non-mutating line-length/style audit, then split declarations and add comments
in focused batches. Avoid changing component APIs or rendered semantics during
the readability pass.

### P2 — Improve content contracts and maintainability

The project currently validates structured JSON with custom Zod wrappers, while
the repository still has multiple parallel content/type modules. Inventory
duplicate contracts and migrate related content to a consistent schema/content
collection approach where it improves editor feedback. Add validation cases for
unsafe links, duplicate IDs, empty descriptions, invalid image dimensions, and
enabled delivery without consent or an endpoint.

### P3 — Add performance and accessibility gates

Run deployed-host audits for LCP/CLS, keyboard focus, contrast, screen-reader
announcements, 200% text zoom, and remote-image loading. Confirm that only the
needed carousel script executes, the first likely LCP image is prioritized by
measurement, and hidden slides remain outside the accessibility tree after
every state transition. Record limits that cannot be verified in CI.

## Suggested execution order

1. Confirm legal copy, production origin, delivery endpoint, and asset rights.
2. Add Playwright smoke coverage and fix the generated-script warning.
3. Enable and stage the inquiry transport with server-side safeguards.
4. Configure production metadata, sitemap/robots, and release-content checks.
5. Apply the 80-column and Astro comment/style cleanup in small reviews.
6. Run deployed performance and accessibility audits and archive evidence.

## Evidence and limitations

The review used source inspection plus `pnpm check` and `pnpm build`. No
production endpoint, deployed host, browser session, network failure, screen
reader, or native zoom behavior was available in this pass; those checks are
explicit follow-up work above.
