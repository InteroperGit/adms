# Извлечение контента в шаблоны

Date: 2026-10-14. Status: planned.

## Цель

Убрать авторский контент из Git-истории и рабочего дерева приложения, сохранив
воспроизводимую структуру данных в `data/templates/`. Шаблоны должны описывать
формат и минимальные примеры, а реальные значения должны поступать из внешнего
источника контента во время подготовки сборки.

## Ограничения и решения

- `data/templates/` остаётся в репозитории и содержит только безопасные
  обезличенные примеры, плейсхолдеры и инструкции по заполнению.
- Реальные JSON/MDX-файлы из `data/content/` не копируются в шаблоны и не
  заменяются механическим переименованием.
- До удаления `data/content/` нужно добавить источник данных, загрузчик и
  проверку полноты. Иначе текущие импорты `src/content/*` сломают сборку.
- Очистка истории — переписывание всех коммитов, поэтому выполняется отдельным
  этапом после проверки репозитория и требует согласования с владельцами
  удалённых веток и тегов.
- Сначала проверяются секреты, персональные данные, внешние URL, изображения и
  текстовые утверждения; шаблоны не должны сохранять такие значения.

## Этапы

1. Зафиксировать инвентарь файлов, импортов, тестов, документации, Git-веток и
   тегов, а также определить внешний источник и формат поставки контента.
2. Создать шаблоны JSON/MDX, схему версии, пример переменных окружения и
   генератор нормализованного набора в изолированный build-каталог.
3. Переключить `src/content/*`, Astro content collections и проверки на
   сгенерированный каталог; добавить ошибку с понятной инструкцией при
   отсутствии входных данных.
4. Обновить тесты, документацию, CI и `.gitignore`; запретить появление
   `data/content/` и реальных экспортов в коммитах.
5. Проверить сборку, контентные контракты, браузерные сценарии и сканирование
   секретов на чистом checkout с шаблонами и на checkout с внешним контентом.
6. После успешной приёмки удалить `data/content/` из текущего дерева и
   переписать Git-историю с последующей проверкой всех refs.

## Критерии готовности

- В репозитории есть только `data/templates/`, генератор и документация по
  поставке контента.
- Без внешнего контента сборка завершается диагностической ошибкой до генерации
  страниц, а не падает из-за случайного `ENOENT`.
- С внешним контентом проходят `astro check`, сборка, контентные и браузерные
  проверки.
- Поиск по всем refs Git не находит удалённые пути `data/content/` и значения,
  попавшие в denylist сканера.
- `.gitignore` исключает runtime-контент, локальные секреты, staging-экспорт и
  временные файлы генератора, но не игнорирует `data/templates/`.

## Data preservation constraint

The existing `data/content/` directory must remain physically present and
byte-for-byte unchanged. Future history cleanup may remove the path from the
Git index and approved rewritten refs, but must never delete or edit this local
ready-data reserve. Record and compare its file hashes before and after.
